# Longriver Android App 产品与系统设计

日期：2026-09-20  
状态：已完成方向确认，等待书面规格审阅

## 1. 产品定位

“Longriver”是一款面向深度历史爱好者和研究型用户的 Android 历史浏览应用。它不以单篇百科文章为中心，而以时间为主轴，把同一时刻不同地区的政权、社会、经济、技术、文化和关键事件并列展示，使用户能够建立全球历史的横向联系。

第一版的核心承诺是：

> 选择内容覆盖范围内的任意年份，快速看清当时世界各地区处于什么状态、发生了什么，以及这些陈述来自哪里。

首批内容范围为 1450–1700 年，重点覆盖东亚、西亚与北非、欧洲、美洲四个大区。内容深度优先于事件数量。

## 2. 设计原则

1. **时间优先**：年份和时间区间是主要入口。
2. **全球对照**：地区以并行泳道呈现，而不是互相隔离的文章。
3. **陈述可追溯**：每条历史陈述都能指向来源、版本和具体引用位置。
4. **不伪造精度**：支持日、年、年代、约数和模糊区间，不把模糊记载改造成精确日期。
5. **争议可共存**：事实、推断和不同学术观点分开保存与展示。
6. **离线优先**：核心阅读功能不依赖持续联网。
7. **云端可更新**：内容通过审核后版本化发布，客户端使用增量包更新。
8. **AI 只辅助**：模型可以抽取候选内容，但不能直接发布历史事实。

## 3. 核心用户体验

主流程：

1. 用户滑动时间轴或输入年份、年代、世纪。
2. App 同屏展示各地区在该时间点的状态摘要。
3. 用户按政治、经济、社会、技术、文化等主题筛选。
4. 用户进入某个事件或状态详情，查看背景、过程、结果、影响及关联实体。
5. 用户展开证据面板，查看来源、版本、页码、摘录、链接、可信状态和争议观点。
6. 用户可以收藏条目、记录私人笔记或沿关联实体继续浏览。

App 默认无需登录。只有跨设备同步收藏和笔记时才要求创建账户；离线阅读和本地收藏始终可匿名使用。

底部一级导航：

- 时间线
- 专题
- 检索
- 收藏

时间线是默认首页。地图不是第一版主界面，后续作为辅助视图加入。

## 4. 第一版功能范围

### 4.1 Android 用户端

1. 全球并行时间线。
2. 年份、年代、世纪跳转，支持公元前后。
3. 地区、政权和主题筛选。
4. 地区状态快照。
5. 事件详情及前因后果。
6. 人物、地区、政权、事件和主题关联跳转。
7. 证据面板：书籍、作者、版本、卷章、页码、原文摘录、稳定链接。
8. 全文检索。
9. 收藏与私人笔记。
10. Room 本地数据库和离线阅读。
11. 云端知识版本检查与增量同步。
12. 内容纠错反馈。

### 4.2 内容管理后台

1. 书目与来源登记。
2. 开放数据导入。
3. OCR 或纯文本接入。
4. AI 候选事件与陈述抽取。
5. 实体匹配与重复检测。
6. 人工审核和引用位置核对。
7. 冲突观点并存与归属标注。
8. 修订记录和审核人记录。
9. 知识版本发布、撤回和回滚。
10. 客户端差量包生成。
11. 用户纠错处理。

### 4.3 后续阶段

- 动态疆域地图和历史航线
- 人物与事件关系图
- 用户自建时间线
- 基于已审核知识库的检索增强 AI 问答
- 多语言内容
- 社区投稿和协同编辑
- 学习测验与课程模式

第一版不包含公开社区编辑、实时聊天、复杂社交系统或未经审核的生成式历史问答。

## 5. 历史知识模型

### 5.1 核心实体

- `Region`：地理地区，可形成层级结构。
- `Polity`：国家、政权、城邦、联盟或其他政治实体。
- `TimeSpan`：开始、结束、精度、历法和不确定性。
- `Snapshot`：某地区或政权在一段时间内的状态陈述。
- `Event`：在某个时间和地点发生的历史事件。
- `Person`：历史人物。
- `Topic`：政治、经济、社会、技术、文化等主题。
- `Source`：书籍、论文、史料、数据库或网页。
- `Edition`：来源的具体版本、出版信息和标识符。
- `Citation`：卷章、页码、段落、原文摘录或稳定链接。
- `Claim`：可独立审核和引用的历史陈述。
- `Relation`：实体间带时间有效期的关系。
- `Revision`：内容修改、审核、发布和撤回记录。

### 5.2 陈述可信度

每条 `Claim` 至少包含：

- 陈述正文
- 适用时间及时间精度
- 关联地区和主题
- 证据类型
- 一个或多个引用
- 内容状态：已证实、学界推断、存在争议、待核查
- 观点提出者或学术归属
- 审核状态和审核人
- 创建、修订和发布版本

来源分为一手史料、学术研究、工具书和开放知识库。开放知识库可以帮助发现信息，但不能自动获得与学术研究相同的证据等级。

## 6. 知识来源与版权边界

### 6.1 可优先接入

- [Wikisource](https://www.wikisource.org/)：公版及自由许可原始文本。
- [Internet Archive](https://archive.org/)：公版书籍、元数据及可用 OCR。
- [Project Gutenberg](https://www.gutenberg.org/)：公版电子书。
- [中国哲学书电子化计划 CTP](https://ctext.org/tools/api/zhs)：通过受限 API 使用中文古籍文本和元数据。
- [Wikidata](https://www.wikidata.org/wiki/Wikidata:SPARQL_query_service)：作为实体、日期、地点和关系的候选骨架。
- [Google Books](https://developers.google.com/books)、[Open Library](https://openlibrary.org/developers/api) 和 [HathiTrust Bibliographic API](https://www.hathitrust.org/member-libraries/resources-for-librarians/data-resources/)：用于书目、版本和可用性检索。
- [中华古籍资源库](https://www.nlc.cn/pcab/zy/szzy/index.shtml)：用于人工检索、原文查证和外部链接；未确认公开批量 API 前不进行自动抓取。

### 6.2 版权规则

1. 只有公版、开放许可或明确获得授权的全文可以进入原始资料库。
2. 受版权保护的书籍默认只存书目、引用位置、必要短引文和外部链接。
3. 每个导入来源记录许可状态、许可文本和获取日期。
4. 来源下线时，保留合法元数据和历史审核记录，但停止分发受限制内容。
5. 不通过绕过登录、访问限制或反爬措施获取资料。

## 7. 内容生产与发布流程

1. **来源接入**：API、开放数据文件或人工登记。
2. **原始资料保存**：保存书目、许可状态、文本或外部位置。
3. **文本处理**：OCR 清洗、章节分割和页码映射。
4. **AI 候选抽取**：提取时间、地点、人物、政权、事件、陈述和引用位置。
5. **自动校验**：检查日期格式、实体候选、重复项和缺失引用。
6. **人工审核**：回看原文，核对引用，处理冲突和不确定性。
7. **发布准备**：生成稳定实体 ID、修订记录和知识版本。
8. **版本发布**：生成全量包与差量包。
9. **客户端同步**：先下载、校验，再原子替换本地版本。
10. **纠错和回滚**：错误内容可在云端撤回，客户端收到更正版本。

AI 生成的任何内容在通过人工审核前都保持未发布状态。

## 8. 系统架构

### 8.1 Android 客户端

- Kotlin
- Jetpack Compose
- Room
- WorkManager
- Retrofit 或同类 HTTP 客户端
- 本地全文检索

客户端以 Room 数据库为主要读取源。网络层负责登录、版本检查、差量包下载、收藏同步和反馈提交。知识包更新不直接逐条修改正式表，而是在临时区域完成下载与校验后原子切换。

### 8.2 服务端

- Python
- Django
- Django REST Framework
- Django Admin
- PostgreSQL
- 定时管理命令或简单任务队列

Django 项目同时承担用户 API、知识同步 API、后台审核、权限管理、导入任务和版本发布。第一版不拆分微服务。

初期检索使用 PostgreSQL 全文检索。只有在数据量和实际查询表现证明有必要时才引入独立搜索引擎。

### 8.3 国内云资源

可选择腾讯云或阿里云：

- 轻量应用服务器或云服务器
- 托管 PostgreSQL
- COS 或 OSS 对象存储
- CDN
- 日志、告警和自动备份

正式面向中国大陆公网服务前，需要完成域名、ICP备案、隐私政策、个人信息处理说明和必要的内容合规工作。

### 8.4 部署形态

第一版使用单体 Django 应用，通过容器化部署。数据库优先使用托管服务，图片、导入文件和知识同步包放入对象存储。AI 抽取采用后台批处理，不进入 App 用户请求的实时链路。

## 9. API 边界

客户端 API 按用途分组：

- `/content/version`：检查当前知识版本。
- `/content/packages`：获取全量包或差量包信息。
- `/search`：云端补充检索。
- `/entities/...`：按需获取未包含在本地包中的详情。
- `/auth/...`：账户登录和令牌刷新。
- `/bookmarks/...`：收藏与笔记同步。
- `/feedback/...`：纠错和内容反馈。

内容导入和审核接口仅供后台使用，与公开客户端 API 分开授权。

## 10. 异常与恢复策略

1. **同步中断**：保留旧知识版本；临时文件可继续下载或安全删除。
2. **校验失败**：拒绝安装差量包并上报错误，不修改正式本地库。
3. **版本不兼容**：请求兼容的全量包或提示升级 App。
4. **来源不可达**：显示最后核验时间；后台定期检查外部链接。
5. **导入冲突**：进入人工审核队列，不自动覆盖已发布陈述。
6. **AI 抽取失败**：保留原始资料和失败原因，可重新处理。
7. **错误发布**：云端撤回版本并发布修正差量；必要时强制回滚。
8. **断网**：已安装内容、检索、收藏和笔记继续可用；联网后再同步。

## 11. 测试与内容质量

### 11.1 软件测试

- 数据模型和 API 单元测试
- 审核与权限集成测试
- 数据库迁移测试
- 全量包和差量包兼容性测试
- 下载中断、校验失败和回滚测试
- Room 数据迁移测试
- 断网和弱网测试
- 关键 Compose 界面测试

### 11.2 内容校验

- 开始时间不得晚于结束时间
- 日期精度和展示文字一致
- 发布陈述必须拥有符合规则的来源
- 引用位置不能为空
- 外部链接定期检查
- 相似事件和陈述重复检测
- 同一实体的别名、旧称和多语言名称去重
- 抽样进行人工复核和跨来源核对

## 12. 实施里程碑

### 里程碑 0：验证内容模型

- 制作可点击原型
- 人工录入并核验 100 条陈述
- 覆盖 1450–1550 年和四个大区
- 验证时间精度、状态快照、事件、关系和引用模型

通过条件：所有示例陈述都能正确展示并追溯到来源，且不存在必须重构数据模型才能表达的核心案例。

### 里程碑 1：云端内容系统

- 建立 Django、PostgreSQL 和审核后台
- 实现来源导入与 AI 候选抽取
- 实现审核、修订、发布、撤回和差量包生成

通过条件：编辑者能够从来源登记开始，独立完成一条陈述的审核和版本发布。

### 里程碑 2：Android 阅读闭环

- 实现全球并行时间线
- 实现筛选、详情、证据面板和检索
- 实现 Room 离线库、收藏、笔记和可靠同步

通过条件：断网状态可以完整浏览已安装内容；同步失败不会损坏旧版本。

### 里程碑 3：扩充首批内容

- 时间范围扩展至 1450–1700 年
- 四个大区拥有连续的状态摘要
- 关键事件具备引用和人工审核记录

通过条件：随机抽查内容均能回到有效出处，争议内容具有明确观点归属。

## 13. 上线标准

1. 核心时间线和详情在断网状态可用。
2. 所有已发布历史陈述都有可验证来源。
3. 同步失败不会破坏本地知识库。
4. 云端知识版本能够撤回和回滚。
5. 未授权全文不进入服务器和客户端分发包。
6. AI 候选内容无法绕过人工审核发布。
7. 完成隐私政策、数据备份和基础安全配置。

## 14. 已确认决策

- 目标用户：深度历史爱好者和研究型用户。
- 核心体验：同一时间横向对照全球各地区。
- 首批范围：1450–1700 年。
- 开发规模：个人独立开发。
- 发布地区：中国大陆优先。
- 产品路线：全球横向剖面为主，史料证据嵌入详情，地图延后。
- 云端路线：国内云资源、PostgreSQL、单体 API 与审核后台。
- 技术路线：Kotlin/Compose/Room + Django/DRF/PostgreSQL。
- 内容路线：开放来源和书目检索辅助，AI 抽取候选，人工审核发布。
